# Handover

This file brings a new contributor, human or Claude Code, up to speed on the
prompt library: what it is, what state it is in, which decisions are settled, and
what to do next. Read it before making changes.

## Purpose

A shared, versioned catalogue of prompts for a loosely connected group of a few
hundred people who use chat interfaces (Claude, ChatGPT, Gemini) rather than APIs.
The repository is the system of record. Each prompt is one Markdown file with YAML
frontmatter. Discovery works through metadata and a generated index, not through
folders. Git provides version history.

The compliance requirement is narrow: no personal data (PII) and no proprietary
data may appear in a prompt. This is handled by convention, not by a heavy system
(see Conventions below).

## Current state

Working and in place:

- Twelve reviewed prompts in `prompts/`, each with complete frontmatter.
- `scripts/validate.py`: schema validation plus a heuristic PII lint. Exits 1 on
  errors so it can gate a pull request. Passes clean on all twelve prompts.
- `scripts/update_index.py`: regenerates `INDEX.md` from frontmatter. Orders by
  curation tier, then produces a full table and a browse-by-tag list.
- `INDEX.md`: generated, current as of the last run.
- `templates/TEMPLATE.md`: the file a contributor copies to start a new prompt.
- `README.md`: contributor guide, schema reference, placeholder convention, PII
  checklist, naming and versioning rules.
- `RANKING.md`: the scoring rationale for the initial twelve prompts.

Not yet done (see Outstanding tasks):

- `README.md` still lists the status values as `draft | reviewed | deprecated`.
  The `proven` tier has been agreed but not written into that schema table.
- No pull request template and no CI workflow yet, so the validator is not yet
  wired to run automatically on a pull request.
- `RANKING.md` sits at the repository root; the agreed structure places
  supplementary docs under `docs/`.

## Metadata schema (authoritative)

Every file in `prompts/` opens with this YAML frontmatter. All base fields are
required. `automation`, `triggers`, and `rank` are optional extensions used mainly
by the automatable prompts.

| Field        | Required | Notes                                                                 |
|--------------|----------|-----------------------------------------------------------------------|
| `title`      | yes      | Short human-readable name.                                            |
| `id`         | yes      | Lowercase kebab-case slug. Must equal the filename stem. Never change it once set. |
| `purpose`    | yes      | One sentence: what it does and when to use it.                       |
| `tags`       | yes      | List. Reuse existing tags where possible.                            |
| `models`     | yes      | List of models it was tuned on.                                      |
| `author`     | yes      | Who contributed it.                                                  |
| `source`     | yes      | `original`, or where it was adapted from.                            |
| `version`    | yes      | Integer, 1 or more. Bump on every meaningful change.                 |
| `created`    | yes      | `YYYY-MM-DD`.                                                        |
| `updated`    | yes      | `YYYY-MM-DD` of the last change.                                     |
| `status`     | yes      | `draft`, `reviewed`, `proven`, or `deprecated` (see tiers below).    |
| `automation` | no       | `interactive`, `scheduled`, `triggered`, or `scheduled-or-triggered`. |
| `triggers`   | no       | List from `cron`, `email`, `slack`, `calendar`. Empty for interactive prompts. |
| `rank`       | no       | Integer. Used only by the initial curated set for ordering.          |

Status tiers, lowest to highest signal:

- `draft`: proposed, not yet reviewed.
- `reviewed`: merged after pull request review. The normal state.
- `proven`: granted by the curation crew as reliably useful. This is the "most
  useful" signal that the index surfaces first. Nothing is `proven` yet; that
  waits until there is real usage to justify it.
- `deprecated`: kept in place for history and stable links; not for use.

`validate.py` enforces this schema. `update_index.py` reads it. If you change the
schema, update both scripts and `README.md` in the same change.

## Conventions and decisions (settled; do not relitigate)

- **Flat `prompts/` folder.** No category subfolders. Prompts are multi-dimensional
  and tags capture that; folders would force one hierarchy and add contributor
  friction. Revisit only past roughly 40 to 50 files, and then only one level deep.
- **Stable ids.** The `id` equals the filename stem and never changes, so links
  stay valid. Renaming is a breaking change.
- **Placeholder convention is the PII control.** Prompts never contain real names,
  numbers, clients, or documents. Situation-specific values are written as
  `[SQUARE_BRACKET]` placeholders and filled in privately at use time. A prompt
  with no real values in it cannot leak any. This is also good prompt design.
- **Review is the compliance gate.** A pull request is reviewed against the PII
  checklist in `README.md` before merge.
- **Deprecate in place.** Set `status: deprecated`; do not move or delete the file.
- **British English** in prose and docs.

## Deferred and out of scope (do not build yet)

The group has decided to keep the system simple until there is proof it is used.
Do not build any of the following without an explicit instruction:

- Likes, favourites, or displayed favourite counts.
- A reviews or ratings system.
- GitHub Discussions or Issues used for voting.
- Any per-user state, backend, database, or web front-end.

The agreed first step for surfacing useful prompts is the `proven` curation tier
above, which needs no new machinery. If richer signals are wanted later, the note
in `docs/RANKING.md` and the earlier design discussion cover the options.

## Tooling

Both scripts run from the repository root and need Python 3 and PyYAML.

```
pip install pyyaml
python scripts/validate.py            # validate all prompts; exit 1 on error
python scripts/validate.py --strict   # also fail on warnings
python scripts/update_index.py        # regenerate INDEX.md
```

`validate.py` checks required fields, types, enum values, that each `id` matches
its filename, and that ids are unique. Its PII lint treats an email address as an
error (fails the run) and a run of seven or more digits as a warning. The lint is
a heuristic backstop, not a replacement for the human review.

Note: the scripts currently depend on PyYAML. If a zero-dependency version is
wanted so they run on a plain Python install, the frontmatter parsing can be
rewritten against the standard library. This has not been done.

4. **Add CI to run the validator.** Create `.github/workflows/validate.yml` that

   when a PR that breaks the schema fails its check.
5. **Optional: split `CONTRIBUTING.md` out of `README.md`.** Move the contribution
   workflow and checklist into `CONTRIBUTING.md`, leaving `README.md` as the
   overview. Only worth it if the README grows unwieldy.

After any change that adds or edits a prompt, run `update_index.py` and commit the
regenerated `INDEX.md` alongside it.

## Definition of done for a prompt change

- Frontmatter complete and `validate.py` passes.
- Placeholders used for anything situation-specific; PII checklist clear.
- `version` bumped and a changelog line added for edits to an existing prompt.
- `INDEX.md` regenerated and committed.
